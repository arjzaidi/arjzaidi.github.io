2. Images vs. image collections

In Lab 1, with DEM data, we dealt with a single Image. Now we move to an Image Collection — a collection of images that is multi-band and multi-temporal.

  • An Image is one scene (e.g. one DEM tile).
  • An Image Collection is a stack of many images (e.g. all Sentinel-2 scenes ever acquired).
  • We filter the collection based on attributes — such as bands, dates, cloud cover, etc.

3. Importing the Sentinel-2 collection

  1. Open a new code window to create a script.
  2. Find Sentinel-2 in the Data Catalog.
  3. Click on the surface reflectance dataset.
  4. Import it using the import button, or copy the code and paste it in the code window:
Code

var S2 = ee.ImageCollection(“COPERNICUS/S2_SR”);

The variable S2 now contains the entire archive of images acquired since the mission began.

4. Filtering the image collection

From the entire collection we limit the number of images according to some criteria — this is called filtering.

FilterFunctionWhat it does
By periodimageCollection.filterDate()Keeps images acquired in a date range
By locationimageCollection.filterBounds()Keeps images covering a given geometry/region
By metadataimageCollection.filterMetadata()Keeps images matching a metadata property (e.g. cloud cover < 10%)

5. Selecting a single image

Is mapping the entire image collection possible? Theoretically yes, but adding a whole collection to the map may end up showing an error due to exceeding the computation time. So we usually select one image.

  • Each image has a unique ID that can be used to access and display it.
  • first() returns the first image from the collection.
  • sort() returns images in ascending or descending order based on a property.
  • Combining sort and first returns the most recent image matching your filters:
Code — most recent image

var mostRecent = S2_2020.sort(‘system:time_start’, false).first();
// false = descending order

Loading a specific Sentinel-2 image

Asset format: COPERNICUS/S2_SR/20151128T002653_20151128T102149_T56MNN

  • The first numeric part = sensing date and time.
  • The second numeric part = product generation date and time.
  • The final 6-character string = unique granule identifier indicating its UTM grid reference.

6. Spectral indices — NDVI

The Normalized Difference Vegetation Index (NDVI) measures vegetation greenness using the near-infrared (B8) and red (B4) bands:

Code — NDVI

var NDVI = image.normalizedDifference([‘B8’, ‘B4’]);

You can also write the same index explicitly with expression():

Code — NDVI with expression

var NDVI = image.expression(
  “(NIR - RED) / (NIR + RED)”,
  {
    RED: image.select(“B4”),  // RED
    NIR: image.select(“B8”),  // NIR
  }).rename(‘NDVI’);
Map.addLayer(NDVI, {min: -1, max: 1}, “NDVI”);

NDVI ranges from −1 to +1: values close to +1 indicate dense, healthy vegetation.
